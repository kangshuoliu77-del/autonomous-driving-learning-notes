## 主要进展

本周的核心变化是从 triangle-based abstraction 转向 corridor-based abstraction。

最初路线：

```text
polygon map
-> constrained triangulation
-> triangle graph
-> formation-aware transition
```

后来发现 triangle graph 太碎，macro-region merge 也不够稳定：

- open area 很难自动合并得优雅
- region 可能非凸
- entry / exit 和 controller 执行边界不清楚
- task label 可能在 merge 中被破坏

因此当前更合适的路线变成：

```text
complex map
-> medial axis / corridor skeleton
-> clearance-aware corridor graph
-> formation-aware DFTS
-> LTL / GR(1) synthesis
-> QP / CBF / CLF refinement
```

## 关键认识

triangle 路线不是完全失败，它明确暴露了 transition system 的关键问题：

```text
transition 不能只看 adjacency
还必须考虑 geometry / formation / controller feasibility
```

shared-edge width 只看门口，不够严谨；Demyen-style through-width 更合理，但在 triangle-level 上继续扩展 stay / switch 会越来越复杂。

ECM / corridor skeleton 的优势是：

- corridor edge 天然对应通道
- edge 可以直接标注 clearance / width / bottleneck
- junction node 更适合表示停留、切换 formation 和任务区域
- formation feasibility 可以从“哪些 triangle 合并”转为“哪条 corridor 支持哪种 formation”

## 当前框架

当前推荐状态空间：

```text
S = (V_c ∪ E_c) × F
```

其中：

- `V_c`：corridor graph 的 junction / terminal / task / switch node
- `E_c`：corridor / passage edge
- `F`：formation set，第一版可用 `{line, compact}`

transition 分层剪枝：

```text
δ_candidate
-> δ_geo
-> δ_form
-> δ_ctrl
-> δ_verified
```

真正的创新不应写成“使用 ECM”，而应写成：

```text
clearance-aware
formation-aware
controller-refinable
transition system construction
```
