## 关键认识

当前不应该把 “skeleton graph” 当成安全证明。

更合理的分工是：

```text
skeleton / ECM:
  topology hint, seed, corridor intuition

convex region / feasibility check:
  safety certificate
```

组会后当前推荐最小闭环：

```text
given map
-> generate path / regions
-> choose feasible formations
-> run controller / QP validation
-> observe transition failure
```

先不接 full temporal logic，先把 geometry + formation + controller 这层跑清楚。

## 当前最小 demo 方案

第一版只考虑：

```text
robots = 3
formations = {triangle, line}
task = A -> C -> B -> A
```

地图要求：

```text
A 到 B 有两条路
一条经过 C，窄，只允许 line
另一条宽，允许 triangle
```

预期行为：

```text
A -> C -> B:
  因为必须经过 C，所以经过窄通道并切换到 line

B -> A:
  不再强制 C，若 triangle cost 更低，应选择宽路并恢复 triangle
```
